---

  - `git_autosync/` — leak-gated auto commit & push tool (CLI `git_autosync.sh` + PySide6
    GUI). gitleaks scans staged changes *and* history before every commit/push; a detected
    secret blocks the repo entirely. This is what actually pushes the other repos to GitHub.
    `autosync_repos.txt` is the source of truth for which repos it pushes — a bare name
    resolves under `active/`, and a subpath (e.g. `toolbox/convert_epub`) works the same way.
    **The file it actually reads is `~/Library/Application Support/git_autosync/autosync_repos.txt`**
    (set via `AUTOSYNC_CONFIG` in the LaunchAgent plist), *not* the copy in the repo. Check
    the effective file, not the repo copy, before assuming a project is backed up: between
    the Sep 2026 reorg and 2026-09-12 it still held pre-reorg bare names, so 7 of its 12
    entries resolved to nothing and were logged as `SKIP (not a git repo)` while the nightly
    run reported success. It now lists 21 entries with correct subpaths (`backstage  push-only`
    added 2026-09-27; on 2026-09-30 `headroom` was removed because `provisio` now carries it,
    the stale `imprint/vidforge` was removed because vidforge is ordinary Imprint source, and
    `provisio` became `push-only` because agents work in it).
    A line may carry a mode flag — `imprint  push-only` — which pushes existing commits
    without sweeping the working tree into an `autosync: <timestamp>` commit. Default is the
    sweep, which is right for a repo nobody edits between runs and wrong for one being
    worked in. Both modes run the gitleaks history scan.
